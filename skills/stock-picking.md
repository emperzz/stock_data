# stock-picking

A 股选股 skill。**流程执行器**——用户有明确选股需求时触发，按选股漏斗从强势板块收敛到具体可买个股候选，输出 chat 精简候选表。

> **核心约束（来自 market-principles）**：本 skill 不绑定任何特定数据 API。正文只描述**每一步需要哪类数据**（板块行情、涨停股池、个股 K 线、公司画像…），**具体端点、参数、source 一律去 `market-data-obtain` 查**——取数时以那里为准，不要凭记忆猜端点。所有判断标准（龙头识别、量价、风险第一）走 `market-principles`，本 skill 只在此之上补充**选股特有的门槛与步序**。

---

## 1. 适用场景

满足以下任一情况时启用本 skill：

- 用户明确要求选股 / 挑票 / "买什么票"
- 用户想要"跟随某龙头 / 某主线的可买跟随票"
- 用户指定某个板块，要求在板块内挑票

**不适用的请求**：

- 市场判断 / 复盘 / 归因 → 走 `market-recap` / `market-principles`
- 仓位 / 止损 / 加减仓 → 交易决策层，本 skill 不覆盖
- 单股深度基本面研究 → 非本 skill 范畴（本 skill 隐含短线视角）

**与 `market-recap` 不冲突**：两者不同触发、不同产物、不同目录，仅有 `recap → market_tracking.md → 本 skill 只读富化` 的单向数据流。本 skill 实时自采板块为主，**不要求 recap 先跑过**。

## 2. 入口双分支

agent 收到选股请求后先判断用户是否**指定了板块**。

**两条分支的对称性**：不论是否指定板块，agent 都必须**先确定板块**（分支 A 多板块扫描 / 分支 B 用户指定单一板块），**再在板块内定龙头**。差别只在分支 A 会对"无龙头"的板块自动排除，分支 B 保留该板块但跳过业务比对。

| 分支 | 触发 | 行为 |
|---|---|---|
| **A. 未指定板块**（默认） | "帮我选票" / "龙头带动的票" | 走完整板块漏斗（§3 步骤 1-5）；每个过闸板块都必须定出龙头，**无龙头的板块自动排除** |
| **B. 指定板块** | "在 X 板块选股" / "X 板块里有什么票" | 跳过板块强势度检测；直接定该板块当前龙头；**无龙头不排除板块**，但跳过 §4 步骤 9 业务比对 |

**全局龙头规则**（两条分支共用）：龙头是**锚定参照**，**不进入选股候选**——龙头是资金热点与板块标杆，但次日溢价已被市场充分定价，不作为本 skill 的可买候选。具体见 §4 各步骤的"龙头锚定"行。

**分支 A 的板块排除规则**：步骤 3 双硬门槛之一"涨停结构"已隐含"必须能定出龙头"——板块内涨停数不足、或涨停候选全部断板/破板/烂板（按 `market-principles §6.7`）导致无龙头候选时，板块自动排除，不进入步骤 4-5。

**分支 B 的无龙头处理**（维持现行行为）：

1. 取指定板块涨停股，按 `market-principles §6` 定当前龙头
2. **有龙头** → 正常走 §4（含业务与龙头比对，步骤 9 可触发）
3. **无龙头**（板块内无涨停）→ 无对标锚点，**跳过业务比对（§4 步骤 9），纯按量价换手 + K 线 + 5 分钟分时选股**

## 3. 板块阶段（分支 A / 默认）

**实时数据为主（权威闸门），tracking 只做事后富化（不增删板块集）。** 每步"要哪类数据"如下，**取数端点去 `market-data-obtain` 查**（板块类数据推荐用其建议的 source）。

### 步骤 1：板块排名筛涨幅
- 要的数据：**带行情的板块清单**（含涨幅），按涨幅排序
- **硬门槛**：涨幅 >1%；**临场**：取排名靠前的

### 步骤 2：取成分股清单 + 全量涨幅排序
- 要的数据：板块的**成分股清单** + **板块内全量股票的当日涨幅排序**
- **重点关注板块内涨幅靠前的股票**——含**未涨停的高涨幅票**（潜在的"后排涨停潜力股"，早于涨停池的结构判断）
- **数据源注意**（不影响选股逻辑，只影响数据完整性预期）：带实时行情的成分股上限 50 只、默认按涨幅倒序——即**板块内涨幅前 50 恰好被完整覆盖**；超出部分为**无报价成员**（行情字段均为 null）。看响应 `quote_truncated` + `quote_total_in_board` 判断是否截断。具体端点与 fallback 走 `market-data-obtain`

### 步骤 3：双硬门槛（成分股数 + 涨停结构）
- 要的数据：**涨停股池**，看板块内涨停分布
- **硬门槛 1**：**板块成分股数 > 10**（资金容量门槛——过小板块资金量不足，大资金不感兴趣）
- **硬门槛 2**：**涨停结构达 3 个 10cm 或 1 个 20cm + 2 个 10cm**（板块动量门槛——满足即可，更强更佳）
- 两个条件**同时满足**才进入步骤 4；任一不满足 → **板块自动排除**（同时意味着无龙头候选）

### 步骤 4：重叠板块去重
- 对成分股**重叠率高**（临场，参考交集/并集 >50%）的板块，**只取涨幅靠前的那一个**
  - **取数建议**：候选板块的**两两成分股交集 + Jaccard**走 `market-data-obtain §9.1` 的 `agent/boards/stock-overlap`（替代手算 N×N set-op）；判定"重叠率 >50%"直接读响应里 `pairs[].jaccard` 字段过滤，对 `intersection` 取并集即可

### 步骤 5：主线归因（兼富化）+ 定龙头

本步统一处理两个问题：**为什么涨**（归因）+ **延续什么主线**（富化）。两者本质都指向"板块上涨的动量源头是龙头"。

- **取数建议**：定龙头前需要"候选板块近期趋势 + 量价 + 顶底"的画像——避免把龙头定在**已走弱板块**。≤5 个过闸板块走 `market-data-obtain §9.1` 的 `agent/boards/batch-profile`（THS 单源；字段与单位见 agent-batch.md）；要长短期趋势各调一次（`"d"` + `"5m"` 共 2 次）

- **主线归因（兼富化）流程**：

  | 优先级 | 条件 | 动作 |
  |---|---|---|
  | **tracking 优先** | 板块名 / 龙头股命中 `market_tracking.md` 中某条 `ml:<slug>` 的**活跃主线**（主线状态 ∈ 活跃）**且**该主线条目最近一次复盘验证日 ≤ **2 个交易日**（今天或昨天验证过） | 直接采用 tracking 里的核心结论 + 连板梯队 + 龙头列表作为归因依据；标注"沿用 tracking `ml:<slug>`, 验证日 YYYY-MM-DD" |
  | **tracking 不命中** | 主线未命中 **或** 信源日期超过 2 个交易日 | 走原流程：调用新闻 / 公告 / 资金流自行归因（`market-principles §8` 强约束——禁止凭模型先验编造） |

  **两条条件必须同时满足**才走 tracking 优先；任一不满足都触发自行归因（避免陈旧主线被误套用于当日异动板块）

- **定龙头**：按 `market-principles §6` 在板块涨停股内做相对比较。**龙头在本 skill 全局规则中是锚定参照，不进入 §4 选股候选**（见 §2 全局龙头规则）

- **tracking 不增删板块集**——本步只对过闸板块贴主线注释，是否纳入板块由步骤 1-3 实时数据决定

## 4. 个股阶段（板块内漏斗）

在每个强势板块内，按以下顺序逐票过滤（前置阶段淘汰的不进入后续）。每步"要哪类数据"如下，**取数端点去 `market-data-obtain` 查**。

**取数策略**：步骤 6-10 是 "per-stock × 多 aspect" fan-out；本 skill 已自限候选 ≤5（§4 步骤 9 双重门控 + 临场人工节流），**优先合并为 `market-data-obtain §9.1` 的 `agent/stocks/batch-profile` 一次调用**（一次调用即返回 quote + features（trend/pivots/volume）+ info + boards）。**features 是服务端计算指标、无 raw K 线**——需要原始日 K 走 `/stocks/{code}/kline`；要日线趋势 **和** 5 分钟分时需**调两次**（`frequency="d"` 一次 + `frequency="5m"` 一次）。同一批候选被步骤 6 / 7 / 8 顺序重复使用时，服务端消化重复请求，无需客户端去重。

> **本阶段顺序**：量价换手（首道硬门槛）→ K 线 → 5 分钟分时软排序 → 业务相似（双重门控）→ 财务 tiebreaker。**量价换手提前**——流动性数据最便宜，先粗筛可省掉对死票的 K 线/分时调用

### 步骤 6：量价换手（首道硬门槛）
- 要的数据：**个股实时行情**（含市值 / 换手率 / 成交额 / **最高价 / 开盘价**）
- **三维度硬门槛**：

| 维度 | 中票 | 小票 |
|---|---|---|
| 换手率 | ≈ 5% | 10-20% |
| 成交额 | ≥ 10 亿 | — |
| **最高涨幅** | **> 5%（最高价 vs 开盘价，**非**收盘涨幅）** | **> 5%** |

- **临场**：尽量不碰大市值票
- **例外**（回引 `market-principles §5.2`）：多日小阳线 + 均线多头排列（健康缓涨）可放宽量能 / 换手要求
- 不满足任一硬门槛 → 直接淘汰，不进入步骤 7

### 步骤 7：技术面（K 线）
- 要的数据：**个股日 K**
  - **取数窗口**：请求**最近 60 个交易日**数据（覆盖 MA60 计算所需的最短窗口）
  - **显示窗口**：形态判断只用**最近 30 个交易日**（老数据会干扰形态判断）
- **MA 指标**：取数时**必须包含 MA60**（作为长期均线锚点识别"远离长期均线"的过涨票）；其他 MA（MA5 / MA10 / MA20 等）使用 `market-data-obtain` 服务端默认提供的即可，skill 不强制枚举
- 优先：短期 K 线**多头排列或走平**、**无顶部压力**、K 线**离 5 日均线不远**（临场）；MA60 作为长期均线锚点参考
- 最佳形态：K 线与均线走平甚至多头排列 + 一根**放量大阳线**

### 步骤 8：分时 5 分钟 K 线（软排序）
- 要的数据：**最近 2 个交易日**的 5 分钟 K 线（当日 + 前一交易日）
- **比较方法**：当日 5 分钟 K 线 vs 昨日同期——当日是否出现明显**放量拉升段**（连续若干 5 分钟 K 线量增价升）
- **承认自然波动**：5 分钟级别量价"有大有小"是常态，重点看**段**（连续区间）而非单根；不需要标记"诱多"等负面信号
- **输出形态**：**软排序因子**——给出每只候选一个 5 分钟量能强度分（弱 / 中 / 强），不强制 pass / fail；强度分作为步骤 9 业务比对前的**优先级权重**
- **龙头锚定**：龙头（龙1）= 锚定参照，不参与 5 分钟量价排序；龙 2+ 的后排涨停票可作为候选（其涨停那一根 5 分钟 K 线通常为当日量能峰值）

### 步骤 9：业务相似（双重门控）
- **触发条件（必须同时满足）**：
  1. **有龙头**（否则跳过本步，纯按量价换手 + K 线 + 5 分钟分时选股——与分支 B 无龙头行为对齐）
  2. **步骤 6-8 后仍有 ≥ 2 只候选**（候选 < 2 时无需业务比对，直接进入步骤 10 财务 tiebreaker 或定选——避免过拟合到不存在的"伪冲突"）
- **方法**：取候选的**主营业务**（公司画像的 `business_scope` 经营范围 + `concepts` 概念标签），与**龙头的主营业务**精确比对
  - **不再做细分赛道粗筛**——A 股板块分类本身多套（同花顺 / 东方财富 / 申万），细分赛道识别依赖券商内部体系外部无法独立验证
- **辅助**：可用**龙头所在板块清单与候选所在板块清单的重叠度**作为加权（重叠高 → 受龙头带动作用预期更强，回引 `market-principles §6.6`）
  - **取数建议**："龙头 + 候选"所属板块**两两交集 + Jaccard**走 `market-data-obtain §9.1` 的 `agent/stocks/board-overlap`（替代逐票手算交集）；`pairs[].jaccard` 直接作"加权"输入
- **不强制筛选**同板块不同赛道的伪相似——"半导体板块里的设备 vs 材料 vs 设计"作为有效候选保留。最终取舍看候选数量是否超出承受范围

### 步骤 10：财务（末位 tiebreaker）
- **仅当**前面筛完候选并列难取舍时才执行
- 对并列候选查盈利：先看**公司画像**里的盈利字段，缺失再 fallback 网络搜索（走 `market-data-obtain §3`）
- 优先选公司业务盈利的

## 5. 工作流

1. 触发本 skill → 前置检查（交易日 / 时点，见 `market-principles §2`）
2. 判断入口分支（§2）：是否指定板块
3. 读 `market_tracking.md`（拿活跃主线做主线归因的 tracking 优先路径）；若今日 `market_recap/{date}.md` 存在可一并参考
4. **两条分支对齐地"先定龙头"**：
   - **分支 A**：执行板块阶段（§3 步骤 1-5），每个过闸板块都已隐式定龙头（步骤 3 双硬门槛之一"涨停结构"保证了龙头候选存在）→ 进入 §4
   - **分支 B**：直接定指定板块的龙头（无龙头则记下"无锚点"，§4 步骤 9 跳过）→ 进入 §4
5. 执行个股阶段漏斗（§4 步骤 6-10）：**量价换手（含最高涨幅）** → K 线 / MA60 → **5 分钟分时软排序** → 业务相似（双重门控）→ 财务 tiebreaker
6. chat 出精简候选表 + 每只候选的详细选择理由（走过步骤 / 量价换手 / 业务比对 / 否决票及否决原因 / 数据来源）

> 注意：龙头是 §2 全局规则的**锚定参照**，不进入 §4 任何步骤的候选列表；本 skill 产出的可买候选是"龙头之外"的票。

## 6. Anti-patterns（不要做）

- **不要**凭记忆猜或写死端点 / 参数 / source —— 取数时去 `market-data-obtain` 查当前端点（服务器端点会变，硬编即漂移）
- **不要**重新定义龙头识别 / 量价原则 / 风险原则 —— 回引 `market-principles §6 / §5.2 / §5.1`
- **不要**把 tracking 主线当"强势板块判定结论" —— tracking 只富化，强弱一律用实时数据重算（分支 A）
- **不要**把硬门槛和临场判定混写 —— 数字明确的（涨幅 >1%、**双硬门槛（成分股数 >10 + 涨停结构）**、**换手 / 成交额 / 最高涨幅**）严格执行，程度词（排名靠前、离 5 日线不远、尽量不碰大市值）临场判定
- **不要**凭模型先验编造涨停/上涨原因 —— 外部事件型原因走 `market-data-obtain` 后总结 + 标注来源；**tracking 优先路径需双条件满足**（主线命中 **且** 信源验证日 ≤2 交易日），任一不满足必须走自行归因
- **不要**用不同板块分类体系混选 —— 全程用同一套（`market-principles §6.2`）
- **不要**做细分板块辨识 —— 细分赛道识别依赖券商内部分类，外部无法独立验证
- **不要**给出交易决策（"建议买入 X 股"/"止损位 N 元"/仓位）—— 本 skill 只产候选，买卖与仓位由用户决定
- **不要**为"最后考虑"的财务给每只票都拉数据 —— 财务只在候选并列时作 tiebreaker（§4 步骤 10）
- **不要**在分支 B（指定板块无龙头）时硬做业务比对 —— 无锚点则纯技术选股
- **不要**把龙头当候选 —— 龙头是锚定参照，**不进入选股候选**（§2 全局规则，分支 A / B 共用）；龙头不在 §4 任何步骤的输出候选列表里
- **不要**用 1 分钟 K 线——分时软排序用 **5 分钟 K 线最近 2 日**；5 分钟量价是软排序因子，不是硬门槛
- **不要**把 §4 步骤 9 当成无条件执行 —— 业务相似是**双重门控**（有龙头 且 ≥2 候选），任一不满足跳过本步
- **不要**用收盘涨幅替代 §4 步骤 6 的"最高涨幅"硬门槛 —— 必须用**(最高价 - 开盘价) / 开盘价**，捕捉盘中拉升后回落的票
- **不要**对每只候选独立拉 4-5 个端点（quote + features + info + boards）——候选 ≤5 时合到 `market-data-obtain §9.1` 的 `agent/stocks/batch-profile`（§4 取数策略）
- **不要**≥2 候选板块时手算两两成分股交集——走 `agent/boards/stock-overlap`（§3 步骤 4 取数建议）
- **不要**≥2 候选股时手算所属板块交集——走 `agent/stocks/board-overlap`（§4 步骤 9 取数建议）
- **不要**为 ≥2 个候选资产手算两两相关性 —— 走 `market-data-obtain §9.1` 的 `agent/correlation/matrix`（服务端算 Pearson + Spearman）
