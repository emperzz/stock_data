# 市场文件协议（每日 md + market_tracking.md）

> **参考资料，非 skill**。配套 `market-principles`（判断方法论）+ `market-recap`（复盘执行器）使用——两者共用本文件定义的目录、模板、写入策略、移除规则、状态切换协议、slug 命名约束。`market-recap` 是实际写入者，`market-principles` 是判断者；模板与协议只在本文件定义一处，两侧按需引用，不重复。

---

## 1. 目录结构与两类文件

- 单一目录，扁平结构
- 路径：`market_recap_dir`（agent 启动时由用户配置，默认 `./market_recap/`）
- 例：`./market_recap/2026-07-15.md` 和 `./market_recap/market_tracking.md` 同目录
- `watchlist-manager` 的 `portfolio.json` / `events.jsonl` 按该 skill 约定落在**同一目录**（"与 market_tracking.md 同一目录"），但那是**用户自建的持仓 / 关注清单**，与本文件的 `market_tracking.md`（复盘产出）**语义独立、互不派生**——`tracking` 的"持续关注的龙头股"是复盘结论，`portfolio.json` 的 `watch` 是用户显式加关注，二者不互相同步。

| 文件 | 命名 | 用途 |
|---|---|---|
| 每日 md | `YYYY-MM-DD.md`（按 A 股交易日） | 当日快照、消息、时点判断、复盘 |
| 持久化文档 | `market_tracking.md` | 跨日延续的"市场记忆"——活跃主线、龙头股、未兑现逻辑等 |

---

## 2. 写入策略

| 文档块 | 策略 | 工具操作 |
|---|---|---|
| 每日 md 顶部"消息"块 | **覆写** | Edit 替换该 section 内容 |
| 每日 md 时间戳"判断"块 | **追加** | Edit 在"判断演化日志"前插入新块 |
| 每日 md "判断演化日志"块 | **追加** | Edit 在该块末尾追加新条目 |
| 持久化文档 `market_tracking.md` | **按需更新**（全量重写或 diff 增量均可） | 每次写每日 md 时视需要同步更新 |

### 2.1 写入前必做

每次写入前先 `Read` 文件，定位到合适的插入点，避免覆盖未处理内容。

### 2.2 任务前后协议

`market_tracking.md` 是跨日延续的"市场记忆"，所有判断都应建立在其最新状态之上：

- **任务执行前**：先 `Read market_tracking.md`，了解活跃主线、龙头股、未兑现逻辑
- **任务执行后**：根据需要按本文件 §2 写策略更新 `market_tracking.md` 和当日 `YYYY-MM-DD.md`

```markdown
（消息获取走 `market-data-obtain`：见 `/news/flash`、`/news/search`、`/news/morning-briefing`、`/news/market-recap` 等端点。）

---

## 判断演化日志

（独立小节，专门记录判断变化过程）

- HH:MM 起判断：...
- HH:MM 修正 → ...（原因：...）
- HH:MM 强化 → ...（新增依据：...）

```

### 模板使用规则

- 顶部"消息"和"复盘"块用 Edit 工具的 replace 模式（每次覆写该 section）
- 时间戳"判断"块用 Edit 工具的 insert 模式（在"判断演化日志"前插入）
- "判断演化日志"按时间正序记录判断变化，14:00 块中如反转 9:30 判断，需在此处显式记录"HH:MM 修正 → ..."
- **首次**写入该日文件时，先 Write 完整模板骨架

### 写作要求

- **保留前因**：本次判断如果反转/强化了前次判断，**必须在研判块里复述前次判断**，让读者理解为何变化
- **文字描述区分**反转与强化（不靠 emoji 或特殊标记，靠自然语言）
- **"原因"块**：外部事件型原因需注明数据来源（哪个端点 / 哪次 fallback 的哪个搜索结果）

## 4. market_tracking.md 模板与协议

```markdown
# 市场追踪与持续关注 [持久]

> 每次判断市场前必读。记录跨日延续的市场上下文，包含活跃主线、龙头股、未兑现逻辑等。

---

## 活跃主线

> **结构化字段规范**：每条主线条目必须使用本文件附录 B 规定的字段（标识 / 状态 / 状态起始 / 核心结论 / 触发条件 / 龙头列表 / 当日引用 / slug 命名说明）。禁止纯自由文本。
> **演化轨迹归 changelog**：本区块是 snapshot（**覆写式**，只保留当前真值），不写"7-21 升级 → 7-22 弱化"等演化过程。演化过程通过 daily 文件的"判断演化日志"章节追溯——tracking 不维护 changelog。

（持续 / 升级中的板块或概念）

- **标识**: `ml:<slug>`（slug 见参考资料 [slug_glossary.md](./slug_glossary.md)）
- **{板块/概念}**
  - **状态**: {活跃 / 减弱 / 失效 / 已归档}
  - **状态起始**: YYYY-MM-DD HH:MM
  - **核心结论**: ≤ 30 字，一句话总结当前判断
  - **触发条件**: [...]（关键词数组，触发当前状态的催化因素）
  - **龙头列表**: [{代码, 名称, 连板数}, ...]
  - **当日引用**: YYYY-MM-DD.md#mainline-<标识>（指向 daily 当日最后一个时点的"主线归因"小节）
  - **slug 命名说明**: slug 命名依据（一句话）
  - **风险标签**（可选）: [机构减仓, 大票回撤, 高位分歧, ...]
  - **下次观察**（可选）: {时间窗口, 观察项}

---

## 减弱主线

> **与"活跃主线"结构相同**，只是 `状态: 减弱`。用于跟踪"曾经活跃但当前信号减弱"的主线——agent 保留 30 天观察期，超期则按本文件"移除规则"直接删除该主线条目（**不归档**）。

（持续 / 减弱中的板块或概念）

- **标识**: `ml:<slug>`（slug 见参考资料 [slug_glossary.md](./slug_glossary.md)）
- **{板块/概念}**
  - **状态**: 减弱
  - **状态起始**: YYYY-MM-DD HH:MM（首次标记为"减弱"的时间）
  - **核心结论**: ≤ 30 字
  - **触发条件**: [...]
  - **龙头列表**: [{代码, 名称, 连板数}, ...]
  - **当日引用**: YYYY-MM-DD.md#mainline-<标识>
  - **下次观察**（可选）: {时间窗口, 观察项}

---

## 持续关注的龙头股

（每条记录包含：当前连板数、上次涨停、所属板块、状态）

- **{股票代码} {股票名}**
  - 所属板块：...
  - 当前连板：N
  - 上次涨停：YYYY-MM-DD
  - 状态：{活跃 / 洗盘 / 震荡 / 待重新评估}

---

## 板块轮动状态

（事件性记录，确认即归档，不持续保留）

- YYYY-MM-DD: 资金从 {X} 流向 {Y} 的迹象

---

## 未兑现的逻辑

（等待兑现的事件 / 数据 / 政策 / 产业趋势）

- **{事件}**
  - 预期兑现时点：YYYY-MM-DD
  - 关联标的：...
```

### 更新规则

- **更新时机**：每次写每日 md 时按需同步更新（不需要独立触发，不需要周末对账）
- **更新方式**：全量重写或 diff 增量均可，效果一样
- **移除原则**：**直接移除，不归档**（tracking 是"当前关注清单"，不是"历史档案库"）；历史通过 daily 文件的"判断演化日志"章节回溯——不在 tracking 重复记录 changelog

### 移除规则（agent 写 tracking 时自动检查）

| 实体 | 保留条件 | 移除触发 |
|---|---|---|
| 活跃主线 | `状态 = 活跃` | state → 减弱时移到"减弱主线"区；DEAD 时**直接移除** |
| 减弱主线 | `状态 = 减弱` + `状态起始 ≤ 30 天` | 超期 → **直接移除** |
| 龙头候选 | 所属主线还在 tracking | 板块龙头当天未涨停 / 市场龙头触发 `market-principles` §6.5 失效标准 / 所属主线移除时 → **直接移除** |
| 板块轮动事件 | 时间 ≤ 7 天 | 超期 → **直接移除**（保留当周内的） |
| 待验证假设 | `预期兑现时点 ≤ 30 天后` + 未兑现 | 超期 / 已验证 / 被证伪 → **直接移除** |

### 状态切换协议（迁移必删源）

> **核心约束**：任意状态切换时，源条目必须从原区域删除（"移到 X 区" = cut + paste，不是 copy + append）。每条主线条目在任何时刻只存在于一个区域。

#### 活跃 → 减弱

主线从活跃切换为减弱时：
- **必须从活跃主线区删除原条目**（防止活跃主线区残留旧版本）
- 在减弱主线区新建条目，状态字段填 `减弱`
- 状态起始字段更新为减弱时间（即 30 天倒计时起点）

#### 减弱 → 重新激活

主线从减弱重新激活为活跃时：
- **必须从减弱主线区删除原条目**（防止两边都有）
- 在活跃主线区新建条目，状态字段填 `活跃`
- 状态起始字段更新为重新激活时间（即 **30 天倒计时归零**——重新激活意味着原"减弱"信号被推翻，重新计时）

#### → 失效

主线进入失效状态时（触发 `market-principles` §6.5 失效标准）：
- 直接从当前所在区域（活跃主线区或减弱主线区）删除原条目
- **无目标区域**——直接删除，不归档、不进任何"已移除"区（tracking 是"当前关注清单"，不是"历史档案库"）

### 操作纪律

写入 tracking 文件时的工具级纪律（适用于活跃主线区 / 减弱主线区 / 其他任何 section）：

- **Edit 原子性**：每次 Edit 操作只改一个 section；改完前不开始下一次 Edit。**禁止**把多个 section 的修改合并到一次 Edit——一次失败会污染多个 section
- **Edit 后 grep 验证**：Edit 完成后立即 grep 该 section 的标识锚点（如 `ml:<slug>`、`<a id="mainline-..."`），确认写入正确、未误改邻近 section。**Edit 后不做 grep = 未完成**
- **不复制完整复盘到 tracking**：tracking 不从 daily 文件复制完整复盘到任何字段；依赖结构化字段（≤ 30 字核心结论 + 当日引用跨跳 daily）保持 tracking 是 snapshot、不是 daily 的镜像

---

**核心原则**：tracking 是"当前需要关注的活跃内容"。**不关注 = 直接从文件移除**，**不归档**。历史通过 daily 文件的"判断演化日志"章节追溯——不在 tracking 重复记录 changelog。

## 附录 A：slug 命名约束（强制）

所有主线 / 龙头 / 板块 / 事件 / 假设条目必须有 `标识` 字段（格式 `<类型前缀>:<slug>`），slug 必须满足以下硬规则。

**硬规则**：
1. 全小写英文 + 连字符分隔（禁止下划线 / 大写 / 空格 / 中文）
2. 不超过 30 字符
3. 禁用通用词（`policy` / `news` / `market` / `industry` / `theme` 等泛词）
4. 禁用纯数字（slug 必须含至少 1 个英文字母）
5. 禁止版本后缀（不允许 `xxx-v2` / `xxx-new` / `xxx-latest`）
6. 同一 `<类型前缀>` 下 slug 全局唯一（创建前必须 grep 已用 slug）
7. slug 一旦创建永不修改（改名 / 合并通过 `MERGED → 新slug` 处理，原 slug 保留作 `已归档`）

**词汇表分级**（L1 行业缩写 → L2 核心词 → L3 驱动因素 → L4 pinyin 兜底，创建顺序从高到低）：**完整分级说明与中文→slug 映射表见 [slug_glossary.md](./slug_glossary.md)**，本文件不重复。

**slug 创建工作流**（强制按顺序执行）：
1. **识别主线范围** — 单一板块→L2；板块复合→L2 取核心驱动；跨板块主题→L3；生僻→L4
2. **查词汇表** — 优先查参考资料 [slug_glossary.md](./slug_glossary.md)，命中即用
3. **全局查重** — `grep "ml:.*<核心词>"` 当前 tracking + daily，已存在则复用
4. **写 `slug 命名说明`** — 强制字段，解释 slug 命名依据
5. **changelog 记录** — 追加 `[slug_creation] <标识> 来源=L<n>(核心词)`

## 附录 B：主线条目结构化字段（强制）

主线条目必须使用以下结构化字段（key 全部中文），禁止纯自由文本：

| 字段（key） | 类型 | 说明 |
|---|---|---|
| `标识` | string | `<类型前缀>:<slug>` 格式，slug 见词汇表 |
| `状态` | enum | `活跃` / `减弱` / `失效` / `已归档` |
| `状态起始` | datetime | `YYYY-MM-DD HH:MM`，当前状态起始时间 |
| `核心结论` | string | ≤ 30 字，一句话总结当前判断 |
| `触发条件` | string[] | 关键词数组，触发当前状态的催化因素 |
| `龙头列表` | object[] | `{代码, 名称, 连板数}` 数组 |
| `当日引用` | string | `YYYY-MM-DD.md#mainline-<标识>`，指向 daily 文件**当日最后一个时点**的"主线归因"小节的具体主线条目（详见本文件 §3）。历史归因通过 daily 文件的"判断演化日志"章节追溯。 |
| `slug 命名说明` | string | slug 命名依据，3 个月后回看时能理解当时逻辑 |
| `风险标签` | string[]（可选） | 机构减仓 / 大票回撤 / 高位分歧 等警示标签 |
| `下次观察` | object（可选） | `{时间窗口, 观察项}`，下次复盘重点观察什么 |

**反模式**：禁止将"演化轨迹"（如"7-21 升级 → 7-22 弱化"）塞进 snapshot 字段。演化轨迹只进 changelog。
